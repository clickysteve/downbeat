# Audio verification

Objective measurements of DOWNBEAT's audio export and live audio, from
`tests/e2e/audio-verify.spec.ts`, run in Chromium 141 (Playwright, headless) against the
production build. Each test builds a controlled pattern at 125 BPM (a sixteenth = 0.12 s =
5292 samples; an engine tick = 882 samples), loads synthetic samples generated by the test
(`tests/e2e/audio-fixtures.ts`; the repository holds no audio files), exports through the real
export path (Slop Factory Core's OfflineAudioContext renderer, the output-processing worklet,
WAV encoding), decodes the WAV files and measures them. Run with `VERIFY_OUT=file.json` to
write the numbers. **No listening tests were carried out**; nothing here is a judgement of
sound quality.

## Findings fixed during verification

- **The master was 6 ms behind the stems.** Chromium's `DynamicsCompressorNode` looks ahead by
  `floor(0.006 × sample rate)` samples (264 at 44.1 kHz). DOWNBEAT now measures that delay and
  Core advances the master by it (`masterLatencyFrames`).
- **The first hit of an exported master was quieter than live.** A compressor created in a new
  OfflineAudioContext attenuates for about 100 ms (a test burst came out at 0.27 instead of
  0.53). Exports now render 0.25 s of silence first and drop it (Core `preRollSeconds`); Core's
  own processors are reset where the music starts, so stems are unchanged.
- **Held sample notes faded over their whole length** (in Core, before 0.2.0): a release
  scheduled ahead started its ramp at the note's start. Core now anchors every fade at its own
  start time.

## Notes

- Measurements use 16-bit files, so "equal" means within one or two 16-bit steps. Chromium can
  sum a node's inputs in a different order between renders, which can move individual samples by
  one step; every note, level and position is the same.
- Live timing is measured in a headless browser with a simulated audio device. In occasional runs
  the first note after PLAY was about 5 ms late (DOWNBEAT's original live time mapping, kept as
  it was), and in one run the live timeline moved by about 20 ms once; the test allows 10 ms per
  interval. Exports do not depend on live timing.
